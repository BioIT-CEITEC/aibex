# Acceptance criteria – Aibex View, first demo

Each criterion has an ID and the test that checks it. A phase is **done** when all its automated tests pass
and the manual checks are recorded in `PROGRESS.md`. Contracts referenced here are in `docs/api.md`.

How to run (from the repo root):
```bash
make test                 # unit tests + ruff (+ frontend typecheck/lint) – no acceptance tests
make accept               # all acceptance tests except live ones
make accept-phase P=2     # one phase
make accept-live          # real e-INFRA model (needs .env); live tests never run without -m live
make e2e                  # Playwright e2e (starts backend with FakeProvider + toy bundle); after T16b
```
Acceptance tests of phases not yet implemented fail – that is expected. A phase's tests must pass once its tasks are done.

## Global (G) – must hold after every task
| ID | Criterion | Check |
|---|---|---|
| G1 | All tests that passed before still pass (no regressions) | `make test`, `make accept-phase` for every finished phase, `make e2e` |
| G2 | `ruff check` clean in backend; `tsc --noEmit` and lint clean in frontend | `make test` |
| G3 | No secrets or real data committed (`.env`, keys, ADAR2 files) | `git diff --cached` review, A3.4 |
| G4 | The app starts with `make dev` and `/api/health` returns ok | manual / e2e webServer |
| G5 | Docs updated when a contract changes (`docs/api.md`, `docs/spec-format.md`, `docs/bundle-format.md`) | review |
| G6 | Every LLM-caused failure is shown in the UI, never crashes the app, never leaves a half-applied spec | A2.2, E2.4 |

## Phase 1 – bundles and dashboard
| ID | Criterion | Test |
|---|---|---|
| A1.1 | Bundles are discovered from `AIBEX_DATA_DIR` | `test_bundles_list_contains_toy` |
| A1.2 | Schema endpoint returns tables, typed columns (declared + inferred), row counts, links | `test_schema_*` |
| A1.3 | Query endpoint is read-only (single SELECT/WITH), capped at 200 by default and clamped to 5000 max; `row_count` is the total | `test_query_*` |

| A1.5 | Spec validation catches unknown tables/columns, duplicate ids, layout mismatch, unsafe `expr` | `test_validate_*` |
| A1.6 | Panel data applies filters and evaluates `expr` server-side | `test_panel_data_*` |
| A1.7 | Airway public bundle can be generated by `scripts/make_airway_bundle.py` | manual (network) |
| E1.1–E1.3 | Dashboard renders ≥4 panels with a Plotly plot and a table, bundle selector, no error banner | `e2e/dashboard.spec.ts` |
| M1 | Visual check: volcano, MA, PCA, heatmap, table readable on 1440×900; screenshot in `logs/screens/` | Playwright MCP |

## Phase 2 – prompt editing (Level 1)
| ID | Criterion | Test |
|---|---|---|
| A2.1 | Sessions with versioned specs, validated patches (422 on invalid, unchanged), undo/redo (409 when nothing to undo/redo, new change clears redo) | `test_session_*`, `test_*patch*`, `test_undo_*`, `test_new_change_clears_redo` (implemented in Phase 1, task T15) |

| E2.1–E2.4 | In the browser: label prompt, filter prompt reduces table rows and its checkbox toggle is a new version, undo/redo buttons, unknown prompt → reply without change | `e2e/chat.spec.ts` |
| M2 | Demo prompts 1–3 and 6 (docs/roadmap.md) work with the real model on the airway bundle; latency noted | manual, record in PROGRESS.md |
